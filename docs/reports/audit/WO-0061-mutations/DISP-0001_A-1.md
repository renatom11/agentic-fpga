### 2.2 dv_lead's claim 1 — `a_hold_end` kills the gate on the inflated cycles: **VERIFIED**

On an all-idle word inside an open frame in state `Frame`:

- `in_preamble` = 0, so `a_pre_mask` = 0x00 (line 308).
- every lane is control and none is `/S/`, `/T/` or `/E/`, so `other_ctl` = 0xFF
  (lines 243–244).
- `a_hold_v = 0xFF &: ~:0x00` = **0xFF**, so `lowest_set` = bit 0 and
  **`a_hold_end` = 0** (lines 328–331).
- `a_closing_v = is_terminate |: is_error |: is_start |: (other_ctl &: a_pre_mask)`
  = 0, so `a_char_end` = 8 (lines 312–318).

`a_close_oversize = a_open &: (cap_end <: a_char_end) &: (cap_end <: a_hold_end) &: (cap_end <:. 8)`
(lines 361–362). Its third conjunct is `cap_end <: 0`, unsatisfiable for an
unsigned 4-bit `cap_end` **at every value of `count`**. The gate is therefore
**dead on exactly the cycle class the I-c1 mutant inflates**, independently of
frame length, start lane, injection depth and the counter's value.

At the one cycle where the cap does come into range — `count` = 1512, `cap_room`
= 6, `cap_end` = 6 — the three comparison conjuncts evaluate `(6 < 8) = T`,
`(6 < 0) = F`, `(6 < 8) = T`. **False.** dv_lead is right.

### 2.3 dv_lead's claim 2 — the 11-bit underflow: **VERIFIED**

`cap_room = of_int ~width:count_bits 1518 -: count` (line 342) at `count_bits`
= 11 (line 148) is an unsigned 11-bit subtraction, so `cap_room` = (1518 − count)
mod 2048. Under the mutant every open-frame cycle adds exactly 8 (covering words
by `cov_count` = 8, held cycles by the seeded constant), so from the `begins`
reload of 0 (line 479) `count(t) = 8t mod 2048` — at a lane-0 start; at a lane-4
start the `Preamble` word covers 4 and `count(t) = 8t − 4`, treated in §2.4 —
and:

- `cap_room ∈ [1,7]` **iff `count` = 1512** — the only multiple of 8 in
  [1511, 1518]. `cap_room` = 6 there.
- the next cycle takes `count` to 1520 and `cap_room` to **2046**, so
  `cap_room >=:. 8` holds, `room` = 8, `cap_end` = 8, and `cap_end <:. 8` — the
  gate's fourth conjunct — is false.

Both figures reproduce exactly.

### 2.4 Where dv_lead's derivation needs correcting — and it does not help me

dv_lead §8 reason 2 states: *"after which `cap_room >=:. 8` is **permanently
true** and `cap_end` saturates at 8. **The cap never binds again for the life of
the frame.**"* As an arithmetic statement about an 11-bit counter that is itself
wrapping, this is **false**. `count(t) = 8t mod 2048` returns to 1512 every 256
open-frame cycles, and the 1518-octet member at k = 7 runs 1513 open-frame
cycles, so the cap re-enters its binding window **six times, not once**:

```
MUTANT 1518 k=7 lane0: cycles=1513 count_next@close=1862 fired=0
  binds=[(189, 1512, 6, 'HELD'), (445, 1512, 6, 'HELD'), (701, 1512, 6, 'HELD'),
         (957, 1512, 6, 'HELD'), (1213, 1512, 6, 'HELD'), (1469, 1512, 6, 'HELD')]
```

(tuples are `(t, count, cap_room, cycle-kind)`; `fired` is the count of cycles at
which `a_close_oversize` evaluated true over the whole frame.)

What actually carries the result is dv_lead's **first** reason extended over all
six: covering words sit at `t ≡ 0 (mod k+1)` = `t ≡ 0 (mod 8)`, and every
recurrence is at `t ≡ 5 (mod 8)` because 256 ≡ 0 (mod 8) freezes the residue at
189 mod 8 = 5. All six are held cycles, so `a_hold_end` = 0 kills the gate at
each. **`a_close_oversize` fires 0 times over the entire frame.** The verdict's
conclusion is correct; one of its two supporting sentences is not, and had 256
not been divisible by 8 the sentence would have been load-bearing in the wrong
direction. Recorded because A-1's own standard requires it, not as mitigation:
**A-1's ruling is unaffected.**

Two further checks in the same direction, both against my disclosure:

- **Lane-4 start, same member, same k.** The first covering word carries 4
  octets, so `count(t) = 8t − 4`, the binding value is 1516 (`cap_room` = 2) at
  `t ≡ 190 (mod 256)`, and 190 mod 8 = 6 — held again. **0 fires.** The
  immunity is not an artefact of the start lane I happened to reason about.
- **k-sweep, N = 1518, lane-0 start, k = 0 … 15.** `a_close_oversize` fires at
  **k ∈ {2, 4, 6, 8, 10, 12, 14}** and never at k ∈ {0, 1, 3, 5, 7, 9, 11, 13,
  15}. The rule is exact: binds occur at `t ≡ 189 (mod 256)`, which is **always
  odd**, so no even `k+1` — no odd k — can ever place one on a covering word.
  **k = 7 is odd.** At a lane-4 start the parity rule does not hold and the
  freeze does instead; k = 7 misses at both.

The last point matters beyond this disposition and is stated as a fact for
whoever seeds this class next: **the I-c1 defect is not structurally unreachable
at REQ-108 — it is unreachable at k = 7.** The same mutant on the same 1518-octet
frame truncates at k = 2. My disclosure's error was therefore not "the class
cannot fail"; it was **claiming a reachability that is a function of the wrapper
depth without ever evaluating that function.** That is worse, not better.

## 3. The process defect, located

The disclosure was not a guess and it was not careless in the ordinary sense —
its arithmetic is correct as far as it goes. It fails structurally, and the
structure is findable at four sites.

**(1) The derivation is a forward fan-out trace, and a fan-out trace cannot
discharge a reachability claim.** Manifest lines 269–283 trace the mutated signal
outward — `count` → `cap_room` → `cap_end` → `cov_end` — and then assert the
consequence: *"`cap_room` falls below 8, `cap_end` binds below `a_char_end`,
`a_close_oversize` rises, the frame is truncated there."* `a_close_oversize` is a
**four-term conjunction**. The trace establishes two of them (`cap_end <:. 8` and
`cap_end <: a_char_end`) because those are the terms the mutated signal feeds.
The term it never names, `cap_end <: a_hold_end`, is **not downstream of `count`
at all** — it is a sibling input contributed by the stimulus, and specifically by
the very cycle type the mutation targets. A trace that walks outward from the
mutated signal is structurally incapable of seeing it. This is the defect class,
and it is general: **fan-out proves the mutated value reaches the gate; it never
proves the gate fires.**

**(2) The claim crossed from arithmetic to behaviour on the word "crossing",
unremarked.** The packet's required consequence (packet lines 258–262) reads
*"MUST cross REQ-108's threshold"*, disambiguated by its own next sentence —
*"that crossing does not happen and the class produces no defect at all"* — into
a claim about an **observable**. My answer established that the *counter* passes
1518 and let the word carry it to the *design's* threshold. Two different
propositions, one word, no derivation between them.

**(3) I wrote the refuting fact myself, 300 lines later, and never propagated
it.** Manifest §3, I-c3, lines 536–537:

> (ii) `a_hold_end` no longer participates in `a_close_oversize`, so a word whose
> hold lane lies below the REQ-108 cap no longer suppresses the truncation.

Read at I-c1 — where `a_hold_v` is untouched and the injected word's hold lane is
lane 0 — that sentence says the hold lane **does** suppress the truncation. The
fact became visible at I-c3 only because there `a_hold_end` was the fan-out root.
Same gate, two entries, opposite roles, no cross-check. This is the same defect
as (1) seen from the other side.

**(4) The manifest's own verification taxonomy has no row for this kind of
claim.** Manifest §5 (lines 1343–1399) enumerates *"what was verified
mechanically"* — syntax, clean application, `sha256` serialisation, column
margins, operator vocabulary — and *"what could not be verified"* — types, widths,
elaboration, combinational loops. Every entry in both lists is a property of the
**diff**. Nowhere is there a category for a **disclosure**, even though the
packet makes the seal a function of the disclosures and therefore makes them the
highest-consequence artefact in the manifest. They were treated as authoring, like
the comments. `J-auditor-0011` (journal lines 2479–2486) shows the same shape:
the escape clauses were *"tested rather than waved past"*, and what was tested for
I-c1 was the counter's total.

## 4. The preventive change, stated as rules for the next manifest round

Both bind on my next campaign and are checkable by whoever adjudicates it.

**R-DISC-1 — a reachability claim is discharged term by term at the firing
cycle, or it is not made.** Where a disclosure asserts that a mutant-induced
event is reachable, the manifest entry must name the **gate signal that produces
the event**, quote its **complete defining expression** from the base file with
line numbers, and evaluate **every conjunct** on the stimulus at the claimed
firing cycle — not only the conjuncts the mutated signal feeds. Conjuncts
contributed by the stimulus rather than by the mutation are called out as such and
evaluated explicitly. Where the firing cycle is selected by modular arithmetic —
a counter landing in a window under a wrapper of depth k — the landing condition
is written as arithmetic in k and shown satisfied **at the k the required
consequence names**, with the recurrence set enumerated rather than assumed
unique. If any conjunct cannot be discharged, the answer is not YES; it is *"the
counter crosses; the observable is not derived"*, which is the packet's own
pre-authorised escape, and **the class is declared NOT SEEDED AS SPECIFIED by me,
in the manifest, before any seal branches on it** — not by the adjudicator
afterwards. Under R-DISC-1 the I-c1 disclosure is a two-line refutation:
`a_close_oversize` line 362 contains `cap_end <: a_hold_end`; the injected word
sets `a_hold_end` = 0; the conjunct is unsatisfiable; escape taken.

**R-DISC-2 — shared gates are tabulated across classes before the manifest is
returned.** Any signal named in more than one class entry gets one row in a
gate-inventory table carrying its full term list and every claim each class makes
about it. A fact one entry relies on and another entry contradicts is a **blocking
defect in the manifest**, repaired before delivery. In WO-0061 `a_close_oversize`
appeared in I-c1 (as the gate that fires) and in I-c3 (as a reach), with
irreconcilable readings of `a_hold_end`'s role, both written by me. The table is
cheap — a dozen rows for ten classes — and it is the mechanical form of the
cross-check that failed here.

**Supporting change to the manifest's §5.** The "verified / could not verify"
taxonomy gains a third list: **behavioural claims made in disclosures**, each with
the method used to discharge it (term-by-term evaluation, arithmetic model,
enumeration) or an explicit statement that it is argued rather than derived. A
disclosure the seal branches on may not sit in the manifest with a weaker evidence
standard than a comment's column width.

The model. Written to a scratch file and run with `python3`; it needs nothing
from the repo but the line numbers above, and it is reproduced in full so this
report is checkable without the scratch file.

```python
COUNT_BITS = 11
MASK = (1 << COUNT_BITS) - 1
OVERSIZE, RUNT, FCS_MIN = 1518, 64, 5

def lowest_index(v):
    return (v & -v).bit_length() - 1 if v else 8

def cycle(state, start4, count, word, mutant):
    kind, lane = word
    a_open = state in ("Preamble", "Frame")
    in_preamble = state == "Preamble"
    cov_first = (4 if start4 else 0) if in_preamble else (0 if a_open else 8)
    a_pre_mask = 0x0F if (in_preamble and start4) else 0x00        # line 308
    if kind == "idle":                                             # lines 243-244
        other_ctl, is_term = 0xFF, 0
    elif kind == "mix":
        other_ctl = (0xFF << (lane + 1)) & 0xFF                    # idles above /T/
        is_term = 1 << lane
    else:
        other_ctl, is_term = 0x00, 0
    a_closing_v = is_term | (other_ctl & a_pre_mask)               # lines 312-313
    a_char_end = lowest_index(a_closing_v)                         # lines 316-317
    a_hold_v = other_ctl & ~a_pre_mask & 0xFF                      # line 328
    a_hold_end = lowest_index(a_hold_v)                            # lines 329-331
    cap_room = (OVERSIZE - count) & MASK                           # line 342
    room = 8 if cap_room >= 8 else cap_room                        # line 348
    s = cov_first + room                                           # line 349
    cap_end = 8 if s >= 8 else s                                   # line 350
    cov_end = min(a_char_end, cap_end, a_hold_end)                 # line 353
    cov_nonempty = cov_end > cov_first                             # line 381
    cov_count = cov_end - cov_first if cov_nonempty else 0         # line 383
    oversize = (a_open and cap_end < a_char_end                    # lines 361-362
                and cap_end < a_hold_end and cap_end < 8)
    held = a_open and not cov_nonempty                             # MUTANT I-c1's gate
    count_next = (count + (8 if (mutant and held) else cov_count)) & MASK   # line 398
    return dict(cap_room=cap_room, cap_end=cap_end, a_char_end=a_char_end,
                a_hold_end=a_hold_end, cov_count=cov_count, held=held,
                oversize=oversize, count_next=count_next)

def run(n, k, mutant, start4=False):
    """Uniform wrapper: k idle cycles at every in-frame word boundary."""
    first = 4 if start4 else 8
    words = []
    if n <= first:
        words.append(("mix", (4 + n) if start4 else n))
    else:
        words.append(("data", 0)); left = n - first
        while left >= 8:
            words.append(("data", 0)); left -= 8
        words.append(("mix", left))
    count, t, fired, binds = 0, 0, 0, []
    for wi, w in enumerate(words):
        r = cycle("Preamble" if wi == 0 else "Frame", start4, count, w, mutant)
        tag = "COVERING" if r["cov_count"] else ("HELD" if r["held"] else "-")
        if 1 <= r["cap_room"] <= 7: binds.append((t, count, r["cap_room"], tag))
        fired += bool(r["oversize"]); count = r["count_next"]; t += 1
        if wi < len(words) - 1:
            for _ in range(k):
                r = cycle("Frame", start4, count, ("idle", 0), mutant)
                tag = "HELD" if r["held"] else "-"
                if 1 <= r["cap_room"] <= 7: binds.append((t, count, r["cap_room"], tag))
                fired += bool(r["oversize"]); count = r["count_next"]; t += 1
    return binds, fired, count, t

for label, args in [
    ("MUTANT 1518 k=7 lane0", (1518, 7, True,  False)),
    ("BASE   1518 k=7 lane0", (1518, 7, False, False)),
    ("MUTANT 1518 k=7 lane4", (1518, 7, True,  True)),
    ("MUTANT 1518 k=0 lane0", (1518, 0, True,  False)),
    ("MUTANT   64 k=7 lane0", (64,   7, True,  False)),
    ("BASE     60 k=0 lane4", (60,   0, False, True)),
    ("MUTANT   60 k=0 lane4", (60,   0, True,  True)),
]:
    b, f, c, t = run(*args)
    print(f"{label}: cycles={t} count_next@close={c} fired={f} "
          f"binds={[(x[0], x[1], x[2], x[3]) for x in b]}")

print("k-sweep, N=1518, lane-0 start:")
for k in range(16):
    b, f, c, t = run(1518, k, True, False)
    print(f"  k={k:<2} binds={len(b):<2} covering-binds="
          f"{sum(1 for x in b if x[3]=='COVERING')} a_close_oversize_fired={f}")
```
