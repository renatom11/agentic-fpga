THE FIRST PRINCIPLES THINKER — opinion for the council

Strip the question to its load-bearing form. The owner wants RE-ADOPTION: a framework that stands up again in a foreign domain, after a first export attempt failed. The council is asked whether PROCESS.md is a complete, accurate, replication-grade DESCRIPTION. Those are not the same question, and the gap between them explains every cluster of findings the three auditors filed. My position: the description is not the export vehicle and cannot be made one; the document is trying to be four artifacts and a fifth thing besides, and the auditors' patch-lists — all individually correct — would grow it toward a 6,000-line third edition of the wrong artifact.

1. Reality has already voted on what the export unit is, and it is not this document. The record shows the actual transfer pipeline: the shell repo (named `generic-agentic-fpga-org` in HT-01 §Feeds — a name PROCESS.md §6.0 never states, per Charlie F1 / Bill F1), a seeded LESSONS file of 44 entries, harvest transits delivered as inbox PRs under a FEDERATION law with sponsor refusal candidate-by-candidate (HT-01, commit 7fb2c99, docs/federation/outbox/). That is a working export mechanism, built by this org, invisible in the document about exporting (Bob F4, C1.6). The shell-unnamed defect is not a missing sentence; it is the inverted dependency showing. The document believes it is the primary artifact with an executable appendix. It is the appendix — the rationale half of a shell-primary unit — and every place it impersonates the machine half, it fails exactly there: zero literal grammars, no trailer keys, no ID templates, no entry header an implementer could code against (Bill F6, Charlie F1; C4.3/C4.5/C5.3 all zero-for-sampled).

2. The document refutes its own ambition, in its own words. §6.3: "Reasons did not regenerate mechanisms even for the people who owned them" — twenty-one ADRs and a 51-case self-test to get from lived incidents to working refusals. ADR-0021: a check is only where it runs. From these two premises the conclusion is forced: NO prose description of an enforcement layer is replication-grade; only the shell plus its self-test plus a doc-shell drift check can be — and §6.0 concedes the drift check "does not exist yet" while calling it "the most useful thing an adopter could build first." Sal's C5.3 (prose complete enough that a reimplementation refuses the same commits) should be ruled against by the council's own weighing rules: it demands a second, unverifiable copy of the rule set, which is §2.4's "rule and its check that disagree" manufactured one level up. Do not condition a pass on mechanism-complete prose. Condition it on the drift test existing and on the document referencing the shell's testable artifacts instead of paraphrasing them.

3. Two document classes have been fused, and the fusion is the root of the readability findings. Append-only ethics — corrections preserved beside claims, margins, stamps, a debt annex — are the org's norms for RECORDS. Applied to a REFERENCE whose declared audience is strangers, they produce exactly Charlie F3 and Bill F8: rules recoverable only from correction narratives, ~135 stamps dangling on a posture list with no path (Charlie F2, Bill F9), an errata apparatus that becomes false-by-inheritance the moment a fork's machinery diverges. Ask what invariant the stamps buy: "every enforcement claim's posture is checkable." The document already delivers that invariant by a cheaper, stronger mechanism — the top-of-file imperative plus §6.2 Step 0 (re-verify every [MC] in YOUR machinery, re-stamp what you cannot trace). For an adopter, Step 0 makes the 135 program-local stamps redundant scaffolding from the correction round, left standing in the shipped structure. The stamped, margined edition is this program's audit record and belongs program-local — the same status Annex B already correctly claims for itself. The exported copy needs the imperative, the postures as a vocabulary, and the museum. That is a fission, not a weakening: not one claim loses truth (Sal guidance 3 satisfied).

4. Bob F1 and F5 are proof of the class, not of the instance. A 128-claim census, seat-by-seat confirmations, a hostile council — and the second edition still shipped a false limb about the amendment machinery (§2.7's "owed test cases still unapplied" vs S29–S37 green inside the very 51-case count §6.3 quotes), and its "closed" taxonomy (§3) was outgrown by the record (HT-01 "EXECUTED", SO's "RE-ISSUED — RE-VERDICT" round 4) essentially while the ink dried. Lesson: per-claim auditing of a 3,000-line prose mirror does not converge; a prose mirror of a living org is a drift generator by construction. The invariant worth exporting is the closure RULE — who may mint a packet type and by what amendment route — while the list of types is an instance that belongs in the shell's packet directory where the drift test can bind it. The document even teaches this distinction (§3.2's ghost-nouns warning, §5.5's "write the number") and then violates it about itself.

5. The decisive test has never been run, and no amount of reviewing substitutes for it. The org's epistemology is explicit: "An unverified protective setting is a belief" — verify by live fire (§6.2 Step 3, C-128). The adoption procedure itself is an unverified protective setting. Its two genesis orders contradict each other and the record (§1.7 machinery-first, G0 rows 1–5 before 6, vs §6.2 review-first — Bill F2); Step 3 is literally unexecutable in sequence on the platform this was built for (required-check picker empty before CI has run — Bill F4, against G0 item 9's own click-path); the DoD arithmetic is uncomputable (Bill F12). These are one finding, not three: §6 has never had its Step 0 run against it. The single most valuable condition this council can set is not a third edition but an ADOPTION LIVE-FIRE — bootstrap a toy program in a foreign domain from the export unit alone, by an agent with no access to this repo, and harvest the trace back through the federation channel that already exists. Every finding class Bill produced by tabletop would surface in hour one of a real one, plus the classes no reader can produce.

6. §5.7 applied one level up: who grades the export? The root class — the author grading its own homework — is discharged everywhere inside the org and nowhere at its boundary. The edition was written by the specification lead, audited by the program's auditor, confirmed by the seats it describes, reviewed by a council the program convened. All interior. For the claim "replication-grade," the only exterior grader is a replication. Until one exists, that claim is precisely the kind of inherited guarantee the document's own first sentence forbids importing. The council should say so in those words.

7. What must not be touched, because it is the part only prose can carry: §5 whole, the failure-class passages under every rule, §1.7's four-act amortized-legitimacy pattern, and the Step 0 imperative. All three auditors converged on this independently (Charlie: "I found no rule I could not state the failure of"; Bill: "strongest of its class"), and it is what C8 exists to protect. Rules transfer; judgment doesn't — this document is the judgment. The fission in point 3 is how you keep a stranger from having to excavate that judgment from under an erratum.

Verdict input: PASS WITH CONDITIONS, but re-scope the conditions rather than multiply them. (a) Name the shell in §6.0 — one line, already known to the record (HT-01). (b) Move every mechanism-completeness obligation (entry/trailer grammars, ID and path templates, packet skeletons, taxonomy list, model-tier launcher facts — Bob F6, Bill F5/F6) into the shell as testable artifacts, referenced not paraphrased. (c) Build the doc-shell drift test the document itself nominates as first-priority. (d) Reconcile §6.2 with §1.7 and the G0 record, then validate §6 by adoption live-fire before the phrase "replication-grade" is used again. (e) Declare the stamped edition program-local; define the fork operation (strip or re-anchor every stamp — Bill F8's missing companion sentence). (f) Fix the two prose falsehoods that survive fission regardless: Bob F1's §2.7 limb, and the sponsor's harvest-refusal power (Bob F3) — sponsor duties are among the few things the prose half must own completely (C5.4), because they are the one place the enforcement chain bottoms out in a human. The owner's question "should it say more about the charters?" gets the same answer at smaller scale: export the auditor charter's mechanism as a shell skeleton (Bill F3), not as more prose here. In one sentence: stop perfecting the description of the machine, ship the machine with its reasons attached, and let one real replication — not a fourth round of reading — decide whether the export works.
