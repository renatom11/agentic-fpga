## F1 — CRITICAL (C5.1): The shell, half the export unit, is never named or locatable

"Read this first" promises: "The other half is an executable shell, named in §6.0" (line 55). §6.0 does not name it. It describes the shell ("the machinery, extracted project-free into its own repository, which an adopter clones and starts from", lines 2575-2577) and gives a kit table whose "Where its original lives" column points only back at "this repository" — the *originals*, never the shell itself. No repository name, no URL, no path, anywhere (grep over all 10 occurrences of "shell" confirms). The shell demonstrably exists — this session's own program history shows it was built into a separate repo — so this is an omission, not a fiction, but from the document alone the adopter cannot obtain the half that runs.

This is fatal because the document *deliberately delegates* everything executable to the shell: "several hundred lines of enforcement script whose value is almost entirely in the incident-hardened details... none of which any prose description will regenerate" (2580-2584). §6.2 Step 0 then instructs: "check them in the shell you have been handed" (2655) — an adopter handed only the document is stranded at the first step of the adoption order. §6.0 is honest that the shell should be treated "as named, not as inspected" (2606) — but it is not even named. One sentence with a repository identifier fixes the single largest adoption blocker in the document.
